# pipeline — 파이프라인 (R3)

출처 표시: `[사용자]` · `[기본값 승인]` · `[임의]` — [purpose.md](purpose.md)와 같다.
이 라운드의 값은 전부 `[기본값 승인]`이다.

## 1. 단계

```
S1 Reference ─▶ S2 Spec ─▶ S3 HTML ─▶ S4 Figma ─▶ 완료
```

| 단계 | story-work 대응 | 하는 일 |
|---|---|---|
| S1 Reference | 1·2번 | uibowl에서 레퍼런스 수집 + 분석, 우리 서비스에 반영할 부분 고르기 |
| S2 Spec | 3번 | 화면 설계 문서 작성 |
| S3 HTML | 6번 (HTML) | 대상 화면 HTML 제작 |
| S4 Figma | 6번 (Figma) | S3 화면을 실제 FME 컴포넌트로 Figma에 옮기기 |

story-work에서 하네스로 옮기지 않은 단계:

| story-work | 처리 |
|---|---|
| 4번 워크플로우 (1920×1000) | S3 HTML이 대신한다 |
| 5번 관계자 협의 | 하네스 밖 사람 단계 |
| 7번 가이드 검토 | S3·S4 판정 스크립트가 대신한다 (P1) |

## 2. 단계별 입출력

| 단계 | 입력 | 출력 |
|---|---|---|
| S1 | 대상 화면명, PRD 해당 시나리오 | 레퍼런스 목록 + 분석 (화면당 레퍼런스 3~5개) |
| S2 | S1 출력, PRD, story-service | 화면 설계 문서 (섹션·지표·컴포넌트 목록) |
| S3 | S2 출력, tokens.css, design.md, Figma 골격 | HTML + CSS |
| S4 | S3 출력, FME 라이브러리 컴포넌트 | Figma 프레임 + HTML↔Figma 대조 결과 |

- S1은 **대상 화면마다 1회**만 한다. 같은 화면을 다시 실행하면 기존 S1 출력을 재사용한다.

## 3. 되돌아가는 지점 (P8)

| 실패 | 돌아가는 곳 | 한도 |
|---|---|---|
| S3 판정 스크립트 실패 | S3 | 3회 |
| S4 HTML↔Figma 대조 불일치 | S4 (원인이 HTML이면 S3) | 3회 |
| S2 설계에 PRD 조건 누락 | S2 | 2회 |
| 한도 초과 | **멈추고 사람에게 알림** — 자동으로 계속하지 않음 | — |
