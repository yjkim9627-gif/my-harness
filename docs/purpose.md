# purpose — 하네스 목적 (R2)

출처 표시: `[사용자]` 사용자가 직접 정함 · `[기본값 승인]` Claude가 제안한 기본값을 사용자가 승인함 · `[임의]` 아직 승인 안 된 값

## 1. 매번 달라지는 것

- **대상 화면 1개** — Production Status / Content Overview / Paid Performance 중 하나 `[기본값 승인]`
- 그 화면에 해당하는 PRD 시나리오 `[기본값 승인]`
- 고정값: 토큰(`tokens/tokens.css`), design.md, 화면 골격, 게이트 규칙 `[기본값 승인]`

## 2. 사용자

- 한 사람(디자이너)이 실행하고 승인한다. `[사용자]`
- 내부 관계자는 하네스를 실행하지 않는다. story-work 5번 협의는 사람 단계로 남는다. `[기본값 승인]`

## 3. 최종 산출물

1. 대상 화면의 **HTML 프로토타입** `[사용자]`
2. 그 HTML 화면을 그대로, **실제 Figma 컴포넌트를 사용해** 옮긴 Figma 디자인 `[사용자]`

## 4. 완료 기준 (한 문장)

> 대상 화면 HTML 1개가 존재하고 판정 스크립트 위반이 0건이며, 같은 화면이 Figma에 실제 컴포넌트로 옮겨져 HTML과의 대조 결과 불일치가 0건이고, 사람 승인 파일에 승인 기록이 있으면 완료다.

- HTML 부분 `[기본값 승인]`
- Figma 대조 부분 `[임의]` — 산출물에 Figma 단계가 추가되면서 Claude가 기본값 문장을 넓혔다. 무엇을 "불일치"로 셀지는 R5에서 정한다.

## 5. 하네스 원칙 `[사용자]`

|---|---|
