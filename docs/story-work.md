# Analytics — Work Stories

이 문서는 "내가 실제로 어떻게 작업했는지"를 기록한다. (AI 없이 손으로 했던 마지막 경험 기준)
"무엇을 위한 일인지"는 [story-service.md](story-service.md)에 있으며, 두 문서는 섞지 않는다.

## 작업 방식 문장

| # | [누가] [무엇을] [한다] | ⏸ 멈칫 → 게이트 | → 넘김 → 경계 |
|---|---|---|---|
| 1 | 내가 uibowl에서 경쟁사 레퍼런스를 수집한다 | **G1** 수집한 레퍼런스 컨펌 | 나 → **uibowl** |
| 2 | 내가 레퍼런스를 분석해 우리 서비스에 반영할 부분을 고른다 | **G2** 분석 결과 컨펌 (분석 → 화면 설계 사이) | 없음 |
| 3 | 내가 분석 내용을 토대로 화면 설계 문서를 구체화한다 | 없음 | 없음 |
| 4 | 내가 Figma에 레퍼런스와 화면 설계서를 반영한 워크플로우를 1920×1000으로 그린다 | 없음 | 나 → **Figma** |
| 5 | 내가 내부 관계자와 협의해 워크플로우와 기능을 확정한다 | **G3** 화면 설계 컨펌 (화면 설계 → 디자인 제작 사이) | 나 → **내부 관계자** |
| 6 | 내가 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 만들고 화면 디자인을 한다 | 없음 | 나 → **Figma** |
| 7 | 내가 완성된 시안의 토큰·컴포넌트가 우리 가이드를 위반하지 않았는지 검토한다 | 보류 (가이드 전달 후 결정) | 보류 |

## 뽑아낸 세 가지

| 구분 | 항목 |
|---|---|
| **명사 → 산출물** | 경쟁사 레퍼런스, 분석 결과(반영할 부분), 화면 설계 문서, 워크플로우(1920×1000), 확정된 워크플로우·기능, 디자인 토큰, 컴포넌트, 화면 디자인 시안, 가이드 검토 결과 |
| **게이트** | G1 레퍼런스 수집 후 · G2 분석 → 화면 설계 · G3 화면 설계 → 디자인 제작 (5번 관계자 협의) |
| **에이전트 경계** | uibowl (1번) · Figma (4번, 6번) · 내부 관계자 (5번) |

## 보류

- **7번 가이드 검토:** 게이트·경계 여부는 임의로 판단하지 않는다. 가이드를 전달받은 뒤 결정한다.
