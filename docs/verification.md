# verification — 검증과 리뷰 (R8)

출처 표시: `[사용자]` · `[기본값 승인]` · `[임의]` — [purpose.md](purpose.md)와 같다.
이 라운드의 값은 전부 `[기본값 승인]`이다.

하네스를 처음 쓰기 전에 아래 순서로 검증한다.

```
① 판정 스크립트 자체 검증 → ② 컴포넌트 이름 보강 → ③ [임의] 값 리뷰 → ④ 시범 실행
```

## ① 판정 스크립트 자체 검증

- `harness/judge/fixtures/`에 규칙마다 **일부러 어긴 예제**를 1개 이상 둔다. ★ 조건(S3-8~10)도 포함한다.
- 규칙을 전부 지킨 예제도 1개 둔다.
- `node harness/judge/selftest.mjs` 통과 조건:
  - 위반 예제가 **전부 실패**로 잡힌다.
  - 규칙을 지킨 예제가 통과한다.
- 2부: 승인 해시(승인 뒤 S2가 바뀌면 무효)와 `run-stage.mjs`의 선행 조건·한도가 지켜지는지 확인한다.
- 하나라도 못 잡으면 하네스를 쓰지 않는다.

## ② 컴포넌트 이름 보강 (S3-7)

- 현재 허용 목록은 Figma 레퍼런스의 9개뿐이라 Analytics 화면에서 S3가 항상 실패한다.
- FME 라이브러리에서 필요한 컴포넌트를 검색해 사람에게 목록을 보여준다. 차트, 지표 카드, 테이블, 탭, 배지 등이 대상이다.
- 승인된 이름만 `rules.json`에 추가하고 `source: "FME library"`를 단다.
- 라이브러리에 없는 컴포넌트는 따로 표시한다. 새로 만들지는 사람이 정한다.

## ③ `[임의]` 값 리뷰 (P9)

- 시범 실행 전에 `rules.json`에서 `"임의"`가 붙은 항목을 전부 표로 보여준다.
- 사람이 항목마다 승인·수정·삭제 중 하나를 고른다.
- 승인된 항목은 `source`를 `"기본값 승인"`으로 바꾼다.
- 현재 대상: 메인 패딩(24, 레퍼런스는 28), Forecast 스타일, 기본 기간 30일, brand-primary·dashed 허용 셀렉터, 레퍼런스 개수 3~5, 지표·기간 별칭, 화면 전환 컨트롤.

## ④ 시범 실행

- 대상: **`content-overview`** — ★ Forecast/Actual 조건을 실제로 확인할 수 있는 화면
- S1 → S4 끝까지 실행한다.
- S2 승인은 사람이 `approval.md`로 한다.
- S4 전에 사람이 `FIGMA_TOKEN`을 설정한다.
- 완료 기준은 [purpose.md](purpose.md) 4절을 따른다.
